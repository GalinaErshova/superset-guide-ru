SQL Lab: проверьте цифры отдельным запросом

Проверить данные SQL-запросом и сохранить виртуальный датасет.

СтабильноНовое6.112 минСверено 2026-11-06

Цель: независимо сверить итоги графика и понять, как из SQL-запроса получается виртуальный датасет. SQL Lab полезен для контроля данных и подготовки запросов, когда визуальных настроек Explore недостаточно.

Понадобятся разрешения на SQL Lab и на учебную базу. Доступ к графику не гарантирует доступ к SQL-редактору. Если пункта меню нет, запросите его у администратора; остальные уроки можно проходить на уже подготовленном датасете.

Узнайте адрес исходной таблицы

Имя датасета в Superset может отличаться от имени таблицы. В описании sales найдите соединение, схему и физическую таблицу либо уточните их у владельца. В примерах ниже таблица называется sales; при необходимости замените её на согласованное полное имя, например training.sales.

Синтаксис кавычек, дат и функций зависит от СУБД. Приведённые запросы используют обычные агрегаты SQL и не меняют данные. Не выполняйте полученный из внешнего источника запрос, пока не понимаете его действие.

Сверьте контрольные суммы

  1. Откройте SQL → SQL Lab; в некоторых сборках пункт называется SQL Lab → SQL Editor.
  2. Выберите учебное соединение и нужную схему. Проверьте их перед запуском.
  3. Вставьте запрос и нажмите Run:
SELECT
  COUNT(*) AS row_count,
  COUNT(DISTINCT order_id) AS order_count,
  SUM(revenue) AS total_revenue,
  SUM(cost) AS total_cost,
  SUM(revenue) - SUM(cost) AS total_profit
FROM sales;

Ожидается одна строка: row_count = 12, order_count = 12, total_revenue = 156000, total_cost = 98000, total_profit = 58000. Это контроль именно полного учебного набора. При RLS или других ограничениях доступа пользователь может видеть меньший срез; его нельзя объявлять полным без проверки прав.

Если количество строк больше числа уникальных заказов, есть повторяющиеся ключи либо пропуски идентификаторов. Посмотрите проблемные группы:

SELECT order_id, COUNT(*) AS rows_per_order
FROM sales
GROUP BY order_id
HAVING COUNT(*) > 1;

Для правильного учебного набора второй запрос не должен возвращать строки. Отдельно проверьте пустые order_id: COUNT(DISTINCT ...) обычно не учитывает NULL.

Сравните регионы

Выполните запрос:

SELECT
  region,
  SUM(revenue) AS revenue,
  SUM(cost) AS cost
FROM sales
GROUP BY region
ORDER BY region;

Сопоставьте каждую строку с графиком. Для выбранного в панели региона сумма выручки и сумма затрат должны совпадать с соответствующей строкой результата. Не сравнивайте график с активным периодом и SQL без ограничения дат: это разные вопросы к данным.

Создайте виртуальный датасет без потери детализации

Для следующего шага выполните отдельный запрос:

SELECT order_id, order_date, region, category, revenue, cost
FROM sales;

Под результатом выберите Create chart или Explore. В окне сохранения датасета выберите Save as new, задайте имя sales_virtual_training и нажмите Save & Explore. Если действие недоступно, проверьте право создания датасетов.

Виртуальный датасет хранит определение запроса; это не автоматически созданная материальная копия данных. Мы оставили одну строку на заказ, чтобы сохранить возможность группировать по региону, категории и дате. Если сохранить уже агрегированный запрос по регионам, из него нельзя восстановить детализацию отдельных заказов.

Упражнение и проверка

Запустите контрольный запрос и запишите пять результатов. Затем откройте виртуальный датасет в Explore и постройте SUM(revenue) без фильтров: ожидается 156 000. Сохранение SQL-запроса в Saved queries и создание датасета — разные операции; убедитесь, что новый объект появился именно в Datasets.
