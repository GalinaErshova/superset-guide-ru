Точечная кастомизация через CSS

Точечные CSS-изменения на копии дашборда и проверка после обновления.

ЭкспериментНовоеЗависит от DOM7 минСверено 2026-11-06

CSS полезен, когда нужна деталь оформления, которую не удаётся выразить настройками графика или темы. В Superset 6.x сначала проверьте систему тем. Старые CSS-рецепты зависят от структуры страницы и могут перестать работать после обновления.

Что будем проверять

Уменьшите или увеличьте один отступ на копии учебного дашборда. Выберите изменение, которое легко увидеть и отменить. Не начинайте с глобальной замены всех стилей приложения.

  1. Скопируйте дашборд и сохраните исходный CSS, если он уже есть.
  2. Откройте инструменты разработчика браузера и найдите нужный элемент.
  3. Убедитесь, что селектор затрагивает только выбранный блок.
  4. Сначала проверьте правило локально в браузере.
  5. Перенесите правило в редактор CSS дашборда, если он доступен в вашей сборке и роли.
  6. Перезагрузите страницу и проверьте обычный режим просмотра.

Пример намерения, а не универсальный селектор

/* Подставьте проверенный селектор именно вашей сборки. */
.your-tested-selector {
  padding: 16px;
}

Этот пример сам по себе ничего не меняет: your-tested-selector — обозначение места для селектора. Не выдавайте его за готовый рецепт для любого Superset. Селекторы с chart ID зависят от конкретного объекта, а nth-of-type — от порядка элементов.

Матрица проверки

Проверьте широкий и узкий экран, длинный заголовок, открытые фильтры, пустой график и обе темы. Сделайте снимки до и после. Запишите версию Superset, селектор, причину изменения и способ отката.

Нельзя скрывать CSS-правилом элемент и считать, что доступ к данным ограничен. Оформление не заменяет разрешения, RLS и настройки публикации.

После обновления

Сначала проверьте исходный дашборд без CSS, затем копию с правилом. Если оформление сломалось, отключите локальное правило и повторно исследуйте DOM. Не добавляйте цепочку !important, пока не понятна причина.
