# Почему дашборд загружается медленно

Сначала найдите медленный график. Общая длительность открытия экрана не объясняет, тратится время на SQL, очередь запросов, передачу результата или его отрисовку.

## Повторяемая проверка

Запишите название графика, период, фильтры, время запуска и длительность. Откройте его отдельно. Повторите тот же сценарий, не меняя сразу пять настроек. Если доступен просмотр сгенерированного запроса, сохраните SQL для сравнения.

| Наблюдение | Что проверить следующим |
| --- | --- |
| Сам SQL выполняется долго | Условия по дате, соединения, объём, план запроса с инженером данных |
| SQL быстрый, таблица тяжёлая | Количество строк и столбцов, необходимость детализации |
| Первый запуск медленный, повторный быстрый | Поведение кэша и допустимую свежесть результата |
| Все графики ждут одновременно | Очереди и доступные ресурсы вместе с администратором |
| Проблема после добавления фильтра | Область действия и запрос значений фильтра |

## Что может сделать аналитик

Ограничить начальный период разумным интервалом. Убрать неиспользуемые колонки и неоправданную детализацию. Разделить обзорный экран и исследование отдельных записей. Проверить соединения: размножение строк одновременно ухудшает скорость и завышает сумму.

Если данные заранее агрегируются в витрине, согласуйте её гранулярность. Витрина по месяцам не позволит корректно показать отдельный день. Ускорение не должно менять смысл метрики.

## Кэш и свежесть

Кэш помогает переиспользовать результаты, но не гарантирует, что данные обновились в источнике. Правила и сроки кэширования задаются в установке. Согласуйте с владельцем отчёта допустимую задержку и покажите дату обновления источника, когда она доступна.

## Как передать проблему

Приложите ссылку на график, точные фильтры, время, длительность и SQL без секретов. Укажите, воспроизводится ли проблема на одном графике и у другого пользователя. Такой пакет полезнее фразы «Superset тормозит».
