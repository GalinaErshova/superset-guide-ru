# Подготовьте и проверьте учебный датасет

**Цель:** убедиться, что исходные поля имеют подходящие типы, а одна строка соответствует одному заказу. Проверка данных нужна до оформления графиков: красивый график с неверной агрегацией остаётся неверным.

Предыдущий шаг: [первое знакомство](01-start.md). Основной маршрут предполагает, что физический датасет `sales` уже создан администратором и доступен вам для чтения. Чтобы менять его описание, нужны права на редактирование датасета. Если их нет, передайте результаты проверки владельцу.

[Скачать учебный sales.csv](/data/sales.csv).

## Как устроен набор

| Поле | Смысл | Ожидаемый тип |
|---|---|---|
| `order_id` | Уникальный идентификатор заказа | Строка или целое число |
| `order_date` | Дата заказа | Date или DateTime |
| `region` | Регион | Строка |
| `category` | Категория | Строка |
| `revenue` | Выручка заказа | Число |
| `cost` | Затраты на заказ | Число |

Не складывайте `order_id`: числовой тип сам по себе не делает поле показателем. `region` и `category` подходят для группировки, а `order_date` — для ограничения периода и временных графиков.

## Проверьте поля

1. В **Datasets** найдите `sales`. Откройте меню действий и **Edit**, если оно доступно.
2. На вкладке **Columns** сравните названия и типы с таблицей выше. У `order_date` должен быть указан временной тип и признак **Is temporal**. Этот признак помогает Superset использовать колонку как время, но не исправляет строки с неверными датами в базе.
3. Проверьте, что `revenue` и `cost` распознаны как числа. Если они строковые, выясните причину в исходном файле или импорте. Удалять символы и приводить типы лучше в согласованном слое подготовки данных.
4. Перейдите в **Explore**, выберите визуализацию **Table** и режим **Raw records**, если он доступен. Добавьте все шесть полей в **Columns**.
5. Установите **Time range → No filter** и удалите дополнительные **Filters**. Нажмите **Run** или **Run Query**.
6. Убедитесь, что лимит строк не меньше 12. Просмотрите все заказы: пустые идентификаторы, повторы, пропуски сумм и неожиданные даты требуют объяснения.

Предпросмотр с ограничением строк помогает увидеть структуру, но не доказывает качество большого производственного датасета. Для него нужны отдельные проверки полноты и уникальности. На нашем небольшом наборе можно сверить все строки; точный SQL-контроль будет в [уроке про SQL Lab](06-sql-lab.md).

## Если нужно загрузить CSV

Файл `sales.csv` — альтернативный способ подготовить упражнение. Superset загружает CSV в выбранную подключённую базу. Нужны подходящий драйвер, доступная схема, разрешённая загрузка файлов и права записи у соединения; наличие кнопки Upload само по себе этого не гарантирует.

В официальном маршруте загрузка находится в **Settings → Data → Database Connections → Upload file to database → Upload CSV**. Выберите учебную базу, схему и новое имя таблицы; для `order_date` укажите разбор как даты. Не выбирайте рабочую таблицу для замены. Если загрузка запрещена, попросите администратора импортировать файл и зарегистрировать физический датасет. Для изучения графиков вам не нужно получать права на управление базами.

## Частые ошибки

- **Виден только недавний период.** Сбросьте Time range: учебные даты могут быть старше текущей недели.
- **SUM недоступна.** Проверьте числовой тип поля, а не только внешний вид значений.
- **Заказов больше 12.** Возможен повторный импорт либо дублирование после соединения таблиц.
- **После обновления таблицы не видно нового поля.** Владелец должен синхронизировать описание датасета с базой; обновление списка графиков не заменяет эту операцию.

## Упражнение и проверка

Составьте короткий паспорт: «Одна строка — один заказ; ключ — `order_id`; дата — `order_date`; показатели — `revenue`, `cost`». Проверьте наличие 12 уникальных заказов. Для всего набора ожидаются `SUM(revenue) = 156000` и `SUM(cost) = 98000`. Не переходите к визуализации с необъяснённым расхождением.
