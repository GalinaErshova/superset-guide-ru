# Superset по-русски

Независимый русскоязычный учебник и справочник Apache Superset для аналитиков, которые создают дашборды.

Целевой адрес: https://superset.galaershova.ru/. Текущая публикация и проверки фиксируются в STATUS.md.

## Содержание

23 материала: восемь последовательных уроков, справочные рецепты, пять экспериментов, релизы и источники. Общий синтетический CSV: 12 заказов, выручка 156000, затраты 98000, прибыль 58000. Базовая версия документации — 6.1.0. Полное прохождение на живой установке Superset не заявляется.

Статусы: **Стабильно**, **Превью**, **Эксперимент**. Новизна материала отдельно: **Новое** и **Обновлено** в течение 30 суток. Лента изменений отделена от дат релизов.

## Сборка

Python 3.11+ и одна зависимость для Markdown:

```text
python -m venv .venv
# Windows:
.venv/Scripts/python -m pip install -r requirements.txt
.venv/Scripts/python build.py
.venv/Scripts/python validate.py
.venv/Scripts/python test_updates.py
# Linux/macOS: .venv/bin/python вместо .venv/Scripts/python
node --check static/app.js
python -m http.server 18963 --bind 127.0.0.1 --directory dist
```

`dist/` полностью генерируется и не редактируется вручную. `build.py` удаляет только собственную папку `dist/` перед сборкой. Сайт статический: без серверных секретов и учётных записей. Поиск загружает собственный JSON. Все страницы читаются без JavaScript; поиск и фильтры каталога требуют JavaScript.

На всех HTML-страницах установлен предоставленный владельцем счётчик Яндекс.Метрики `114109969`: Вебвизор, карта кликов, отслеживание ссылок, точный показатель отказов, `ssr` и `ecommerce: "dataLayer"`. Скрипт асинхронно загружается с `mc.yandex.ru`; без JavaScript используется пиксель. События электронной торговли сайт самостоятельно не отправляет. Счётчик находится в общем шаблоне `build.py` и включается также в локальную сборку.

## Как обновить материал

1. Измените Markdown в `content/`. Первая строка — `# Заголовок`.
2. В `content/catalog.json` обновите поля `updated` и `checked` (`YYYY-MM-DD`). `published` сохраняется. Начальные значения всех трёх полей — 2026-11-06.
3. Для нового материала добавьте строку каталога с уникальным `slug`, файлом, разделом, кратким описанием, временем чтения и статусом. `status`: `stable`, `preview`, `experiment`. Укажите `version`, `published`, `updated`, `checked` явно.
4. Добавьте запись в `content/updates.json` при содержательном изменении. Дата новости о проверке не подменяет дату выхода релиза.
5. Релизы меняйте в `content/releases.json`: версии, статусы, даты публикации, URL и дату сверки. Из этого файла строятся и таблица релизов, и сводка «Что нового». Подробные пояснения остаются в releases.md.
6. Ссылки между уроками вида `02-data.md` сборщик преобразует в маршруты. В новых справочных статьях используйте `/guide/<slug>/`.
7. Проверьте источники, сборку и `validate.py`. При изменении числа страниц обновите ожидаемое количество в проверке. Проверьте поиск и фильтры в браузере, широкую и узкую ширину.
8. Работайте в своей ветке. Публикуйте проверенный коммит после независимого ревью. Main напрямую не редактировать.

Новости не собираются и не публикуются автоматически. Atom (`/feed.xml`) отражает редакционный журнал после новой сборки.

## SEO

Общий шаблон формирует уникальные `title` и `description`, HTTPS canonical, robots, Open Graph и Twitter Card. Название и описание берутся из материала и каталога; язык сайта — русский. На статьях добавлены тип `article`, даты и раздел. JSON-LD описывает WebSite, WebPage, Article с автором и редакционными датами, а также BreadcrumbList. Дата проверки источников не подменяет дату изменения статьи.

Поиск и 404 имеют `noindex, follow` и исключены из sitemap. Остальные 28 адресов открыты для индексации. robots.txt разрешает обход, включая чтение noindex, и указывает sitemap.xml. `validate.py` проверяет метаданные, JSON-LD и совпадение карты сайта с индексируемыми страницами. Регистрация в Google Search Console/Яндекс Вебмастере и отправка sitemap не выполнялись; метаданные не гарантируют индексацию или позиции.

## Источники и авторство

Собственные объяснения, учебный датасет и задания сопровождаются ссылками на источники. Материалы Apache, Preset и сторонних авторов не копируются целиком. Свойства стороннего Preset Cloud не выдаются за гарантированные возможности Apache Superset. Условия лицензирования сторонних материалов определяют их авторы; сайт не меняет их права.

## Публикация через GitHub Pages

Исходники: ветка `codex/superset-guide`, PR в `main`. Сборка публикуется отдельной веткой `gh-pages` из проверенного коммита; main напрямую не меняется. GitHub Pages использует корень `gh-pages`, файл CNAME и .nojekyll. DNS: CNAME `superset` → `GalinaErshova.github.io` (без пути репозитория). Запись A того же имени необходимо заменить. Публикация не требует сервера Alex.
